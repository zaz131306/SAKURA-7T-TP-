# 1. ОБЩИЕ ПОЛОЖЕНИЯ

## 1.1. Наименование и шифр изделия

Изделие — программно-аппаратная платформа распределённых вычислений, криптостойкого управления и нейро-символической обработки **«Sakura Stack»**.

- Шифр ОКР: «Sakura Stack»;
- Шифр технического проекта: **SAKURA-7T-TP**.

## 1.2. Основание для разработки

Работа выполняется на основании договора/госконтракта между Заказчиком и Исполнителем. Реквизиты (номер, дата, стороны, этапы, финансирование, права на ИС, экспортные ограничения) фиксируются в Приложении 1 (шаблон) и в настоящем ТП не приводятся.

**Блокирующее условие:** до утверждения договорной базы настоящий ТП считается проектом.

## 1.3. Исполнители и соисполнители

| Роль | Функция | Обязательные подтверждения |
|---|---|---|
| Исполнитель-1 | Системная интеграция, архитектура, ПО, криптоконтур, приёмка | Договорная база, NDA, допуск |
| Соисполнитель-А | Аппаратная разработка | AVL, DFM/DFT |
| Соисполнитель-Б | Математическое моделирование, формальная верификация, AI safety | NDA |
| Соисполнитель-В | Производство и сборка | Производственная аккредитация |
| Соисполнитель-Г | Испытательная лаборатория | Аккредитация, область испытаний |
| Соисполнитель-Д | Криптографический подрядчик | Лицензии ФСБ/ФСТЭК |

Наименования организаций в тексте не фиксируются.

## 1.4. Сроки выполнения ОКР

48 месяцев с даты утверждения ТП. Календарный план, WBS, stage gates — раздел 18.

### 1.5.1. Правило применения стандартов

Используются действующие редакции на дату утверждения; точные обозначения — в ВД-1.

Запрещается:

- использовать иностранные стандарты как обязательные без обоснования и approval;
- применять военные стандарты в гражданской baseline без требования Заказчика.

### 1.6.2. Lifecycle phases и operating modes (с BC-22)

**Lifecycle phases (BC-22, LIFE-001):**

| Фаза | Описание |
|---|---|
| PROVISIONING | Производство, настройка, ceremony |
| OPERATIONAL | Штатная эксплуатация |
| DEGRADED | Сниженная работоспособность |
| ISOLATED | Локальный/изолированный контур |
| RECOVERY | Восстановление |
| DECOMMISSION | Вывод из эксплуатации |

**Operating modes (BC-22):**

| Режим | Описание |
|---|---|
| NORMAL | Штатная работа |
| BFT_MODE | Защита от византийских отказов |
| CFT_MODE | Повышенная производительность в доверенной среде |
| DEGRADED_NET | Потеря части каналов |
| DEGRADED_COMPUTE | Недоступность части узлов |
| ISOLATED | Локальный контур |
| AIR_GAP | Полная изоляция |
| MAINTENANCE | Обслуживание |
| TRAINING | Изолированное обучение |
| SECURE_LOCKDOWN | Блокировка небезопасных операций |
| EMERGENCY_STOP | Остановка управляющих воздействий |
| RECOVERY | Восстановление |
| LOCKED | Заблокирован |
| SANITIZING | Уничтожение данных |
| DECOMMISSIONED | Выведен из эксплуатации |

**Mapping phase → mode (BC-22, LIFE-001a):**

| Lifecycle phase | Допустимые operating modes |
|---|---|
| PROVISIONING | MAINTENANCE, TRAINING |
| OPERATIONAL | NORMAL, BFT_MODE, CFT_MODE |
| DEGRADED | DEGRADED_NET, DEGRADED_COMPUTE |
| ISOLATED | ISOLATED, AIR_GAP, SECURE_LOCKDOWN, EMERGENCY_STOP |
| RECOVERY | RECOVERY, MAINTENANCE |
| DECOMMISSION | LOCKED, SANITIZING, DECOMMISSIONED |

**Нормативное требование:**
```
LIFE-001 (v2.3)
MUST: узел имеет нормативные lifecycle phases.

LIFE-001a (v2.3)
MUST: внутри каждой lifecycle phase разрешены только operating modes по таблице сопоставления.
MUST: переходы phase/mode фиксируются в audit log с причиной, инициатором, attestation state и timestamp.
V: I/D/T
```

| Уровень | Название | Разрешено | Запрещено |
|---|---|---|---|

| Домен | Содержание | Уровень |
|---|---|---|
| T0 | Внешние сети | Недоверяемый |
| T1 | Датчики, IoT | Ограниченно доверяемый |

## 1.7. Классификация изделия

- Вид: программно-аппаратный комплекс.
- Категория сложности: 2-я; крипто- и высокоскоростные интерфейсы — элементы 1-й.
- Стадия: опытный образец → мелкая серия → серия.
- Климатическое исполнение: по конфигурации (ВД-1).
- Степень защиты: IP54 (портатив), IP20/IP31 (стоечный).
- **Не взрывозащищён** в baseline.
- **Не является оружием**, не обеспечивает автономный выбор/поражение целей.
- Лазерная безопасность: Class 1 по IEC 60825-1.
- Биометрия (опция): не медицинское изделие; принципы IEC 60601-1 (BF); ток утечки ≤10 мкА норма / ≤50 мкА единичный отказ; дефибрилляционная защита 5 кВ/10 мс; развязка ≥2 МОм @1500 В RMS 1 мин; ISO 10993.

## 1.8. Гриф

ДСП и/или коммерческая тайна; при признаках гостайны — отдельный регламент. Маркировка: гриф, номер экземпляра, «лист __ из __», подпись, дата, шифр, ограничение копирования. Допуск — по списку, need-to-know; иностранные граждане — только по отдельному разрешению.

## 1.9. Экспортный контроль

До утверждения ЭК-1 запрещены: отправка документации за рубеж, публикации, зарубежные облака, передача исходников, open-source, иностранные специалисты без approval.

Поля маркировки: `export_control_class`, `license_required`, `destination_restriction`, `end_user_certificate`, `encryption_registration_code`.

## 1.10. Патентная чистота и FTO

До ПДР — FTO-отчёт: поиск по МПК G06F, H04L, G06N, H01S, H01L, G01S, H04B; юрисдикции РФ/ЕАЭС/US/EP/CN/JP/KR; claim chart по BFT/CFT, CRDT/DAG, HSM/tamper, ГОСТ/PQ hybrid, template protection, model attestation; юридическое заключение; меры. Отрицательное FTO-заключение запрещает production-релиз.

## 1.11. Класс СКЗИ (с BC-16)

Baseline: **КС3** по требованиям ФСБ России (если иное не установлено Заказчиком).

Обоснование: защита конфиденциальной информации (не гостайна), доверенное управление распределёнными контурами, ГОСТ-алгоритмы, HSM, PKI, attestation, защищённые обновления.

**BC-16:** FIPS 140-3 — только supplementary/reference профиль; не заменяет российскую сертификацию/аттестацию СКЗИ и не может быть единственным основанием для production-конфигурации baseline.

КС1/КС2 — только специальная модификация; смешение классов в production-конфигурации запрещено.

**Блокирующее:** без подтверждённого класса доверия и лицензий разработка production-криптомодулей не начинается.

# 2. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

## 2.1. Назначение

1. Защищённое распределённое управление критическими контурами.
2. Инференс нейросетей на периферийных узлах.
3. Контролируемое инкрементальное/федеративное обучение без выгрузки сырых данных.
4. Геораспределённое консенсусное хранение состояний.
5. Семантическая аналитика CRDT/DAG.
6. Нейро-символическая поддержка решений с PDDL-верификацией.
7. Опциональная биометрическая аутентификация с защитой ПДн.
8. Наблюдаемость, аудит, attestation, безопасные обновления.

## 2.2. Область применения

Ситуационные центры; КИИ; энергетика; транспорт; промышленная автоматизация; защищённая связь/ВКС; edge AI; ГИС.

## 2.3. Исключения из baseline

1. Орбитальные узлы как обязательные элементы консенсуса.
2. Прямое управление поражающими средствами.
3. Автономный выбор цели.
4. Автономное применение силы.
5. AGI-функции.
6. Обязательный фотонный межчиплетный интерфейс 16 Тбит/с.
7. Зависимость от одного иностранного foundry/IP/компонента без fallback.
8. Обязательный tapeout без подтверждённого контракта.
9. Обязательный HBM без подтверждённой доступности (baseline — LPDDR5X, HBM2e — опция SAKURA-A).

# 5. СИСТЕМНАЯ АРХИТЕКТУРА

## 5.1. Восемь слоёв

Строгая иерархия: команда — сверху вниз, доверие — снизу вверх. Каждый слой зависит только от нижележащих и не может быть скомпрометирован через вышележащие.

| Слой | Название | Назначение |
|---|---|---|
| L0 | Trust Anchor | Аппаратный корень доверия |
| L1 | Compute Platform | Вычислительная платформа |
| L2 | Crypto Core | Криптографический контур |
| L3 | Cognitive Core | Нейро-символический интеллект (внешний, T8) |
| L4 | Policy & Ethics | Этический и политический контроль |
| L5 | Isolation & Execution | Изоляция и исполнение |
| L6 | Consensus & Distribution | Распределённый консенсус |
| L7 | Observability & Audit | Наблюдаемость и аудит |
| L8 | Lifecycle | Жизненный цикл |

```
OPERATOR / EXTERNAL SYSTEMS
  │ mTLS + PQ + RBAC/ABAC + MFA + audit
  ▼
L7 Observability & Audit   — immutable audit, hash chain, replay, SIEM, DR
  │ signed telemetry, no direct actuation
  ▼
L6 Consensus & Distribution — SakuraBFT/CFT, quorum 2f+1=7, view change
  │ consensus-bound commands
  ▼
L4 Policy & Ethics         — Authority Kernel, Ethics Governor, autonomy ≤ L3
  │ policy-gated actions, veto power
  ▼
L5 Isolation & Execution   — bwrap, eBPF, SECCOMP, sandbox, zeroize
  │ isolated execution, no network, no root
  ▼
L3 Cognitive Core          — SLM 14–32B (LLM 405B — внешний слой SAKURA-A, T8)
  │ verified plans only, sandboxed inference
  ▼
L2 Crypto Core             — ML-KEM-1024, ML-DSA-65, ГОСТ, HSM, PKI, TRNG
  │ keys never leave HSM, PQ hybrid
  ▼
L1 Compute Platform        — Versal Premium, AIE, LPDDR5X (HBM2e — опция), FPGA, ARM
  │ secure boot, attestation, tamper detection
  ▼
L0 Trust Anchor           — HSM, TEE, secure boot, tamper mesh, sensors
```

## 6.2. Тепловой расчёт (с BC-29)

### 6.2.1. Исходное положение

```
P_heat ≈ P_elec
```

### 6.2.2. Сводная таблица

| Объект | P, Вт | Tamb, °C | Tj limit, °C | Target Tj, °C | θJA треб., °C/Вт |
|---|---:|---:|---:|---:|---:|
| Узел L1 (непрерывно) | 65 | 55 | 105 | ≤95 | ≤0,615 |
| AI-узел | 30 | 55 | 105 | ≤95 | ≤1,33 |
| **HSM (BC-29)** | **2** | **55** | **85** | **≤75** | **≤10** |

Формулы: `ΔT = P·θJA`; `Tj = Tamb + ΔT`; `θJA = θJC + θCS + θSA + θAMB`.

### 6.2.3. Расчёт узла L1

- P = 65 Вт; Tamb = 55 °C; Tj max = 105 °C; target Tj ≤95 °C;
- θJA треб. = (95−55)/65 = 0,615 °C/Вт;
- конструкция: θJC=0,10; θCS=0,15; θSA=0,30; θAMB=0,05; θJA=0,60;
- Tj = 55 + 65×0,60 = 94,0 °C ✓ (запас 11 °C).

Подтверждение: CFD + стендовые испытания (Gate 3).

### 6.2.4. Пиковый режим узла L1

Пик 150 Вт в непрерывном режиме недопустим (Tj = 145 °C > 105 °C). Пик допустим за счёт тепловой инерции:

- тепловая ёмкость узла ≈ 900 Дж/К;
- избыточная мощность пика 150 − 65 = 85 Вт;
- прирост за 30 с: ΔT = 85×30/900 ≈ 2,8 °C → Tj ≈ 96,8 °C ✓.

Правило: пик ≤150 Вт длительностью ≤30 с под контролем TCU; при превышении — DVFS-throttling.

### 6.2.5. Расчёт AI-узла

- P = 30 Вт; θJA = 1,33 °C/Вт; Tj = 55 + 30×1,33 = 94,9 °C ✓.

### 6.2.6. Отказ вентилятора

При отказе вентилятора θSA ухудшается 0,30 → 0,90, θJA(fail) = 1,2 °C/Вт.

- допустимая мощность: P ≤ (95−55)/1,2 = 33 Вт → норма ≤30 Вт (Tj = 91 °C);
- превышение → safe mode.

При отказе всех вентиляторов: controlled shutdown ≤30 с; сохранение критических состояний; zeroize session keys.

### 6.2.7. HSM (BC-29)

- P = 2 Вт; Tj limit = 85 °C; target Tj ≤75 °C;
- θJC = 1,00; θCS = 2,00; θSA = 5,00; θAMB = 1,00; θJA = 9,00;
- Tj = 55 + 2×9 = 73 °C ✓; запас до 85 °C = 12 °C.

```
V: T/A/S
```

# 9. ЭЛЕКТРОМАГНИТНАЯ СОВМЕСТИМОСТЬ

## 9.1. Требования

Baseline гражданский: CISPR 32 Class B / ГОСТ Р 51317 (эмиссия), IEC 61000 (иммунитет). MIL-STD-461 / ГОСТ РВ — только special. TEMPEST — только при гостайне.

## 9.2. Входной фильтр

```
fc = 1/(2π√(LC)) = 1/(2π√(10×10⁻⁶ × 1000×10⁻⁶)) = 1/(2π×10⁻⁴) ≈ 1,59 кГц ✓
```

Затухание: 20 дБ/дек (один реактивный элемент), 40 дБ/дек (LC), 60 дБ/дек (CLC). Учёт паразитов (ESL, ESR, self-resonance, взаимные связи, индуктивности трасс и разъёмов) — обязательной моделью; практическое затухание ≥60 дБ в целевом диапазоне подтверждается S-параметрами и стендом.

## 9.3. Экранирование и расчёт SE

Эффективность экранирования определяется худшим элементом, а не суммой:

- материал (алюминий 1 мм) на 1 ГГц: отражение + поглощение >>60 дБ — материал не лимитирует;
- апертура доминирует: `SE_slot = 20·log₁₀(λ/2d)` для одиночной щели длиной d (худший случай, резонанс при d = λ/2);
- λ(1 ГГц) = 300 мм; d = 15 мм → `SE_slot = 20·log₁₀(300/30) = 20 дБ`;
- для SE ≥60 дБ требуется d ≤ λ/200 = 1,5 мм, либо волноводный эффект (глубина щели ≥5×ширины), либо несколько малых отверстий (SE растёт ~10·log₁₀(n⁻¹)).

Проектное правило: все швы — с EMI-прокладками; сплошные щели запрещены; контроль зазора и затяжки — в DFM.

## 9.4. Заземление

Разделение ground (digital/analog/RF/power/chassis); bonding <2,5 мОм до 100 МГц; фильтрация всех внешних кабелей.

## 9.5. Обязательные EMC-артефакты

Модель фильтра с паразитами; измерения emissions/immunity; отчёт shielding effectiveness; отчёт grounding; протокол аккредитованной лаборатории. Gate: без EMC-отчёта production не допускается.

# 12. GNSS / PTP / HOLDOVER

## 12.1. Требования

GNSS-disciplined OCXO; **holdover ≤5 мкс за 24 ч (TARGET ≤3 мкс); ≤150 мкс за 7 суток (OCXO)**; для ≤10 мкс за 7 суток — рубидиевый стандарт (опция) либо обязательный re-sync не реже 1 раза в 24 ч; анти-spoofing/jamming; RAIM/ANF; альтернативный источник времени; timestamp ≤1 мкс внутри площадки, ≤10 мкс гео.

**Изменение требования (BC-2, v2.1):** было ≤1 мкс/24 ч и ≤10 мкс/7 сут; стало ≤5 мкс/24 ч и ≤150 мкс/7 сут. Причина: исходные значения занижены — модель ред. 1.0 приравнивала Allan deviation к константной частотной ошибке и игнорировала старение OCXO.

## 12.2. Модель осциллятора

| Параметр | OCXO baseline | TCXO fallback |
|---|---|---|
| y₀ | ≤1×10⁻¹¹ | ≤1×10⁻⁹ |
| Старение a | ≤5×10⁻¹¹/сутки | ≤5×10⁻⁹/сутки |
| Температурный коэф. | ≤1×10⁻¹⁰/°C | ≤5×10⁻⁹/°C |

Дрейф holdover:
```
Δt(T) = y₀·T + ½·a·T²
```

24 ч (T = 86 400 с; a = 5×10⁻¹¹/сут = 5,79×10⁻¹⁶ 1/с):
- y₀·T = 1×10⁻¹¹×86 400 = 0,864 мкс;
- ½·a·T² = 0,5×5,79×10⁻¹⁶×(86 400)² = 2,16 мкс;
- итого ≈3,0 мкс → MUST ≤5 мкс выполняется.

7 суток (T = 604 800 с):
- y₀·T = 6,05 мкс;
- ½·a·T² = 0,5×5,79×10⁻¹⁶×(604 800)² ≈ 106 мкс;
- итого ≈112 мкс → MUST ≤150 мкс выполняется; для ≤10 мкс за 7 суток OCXO недостаточно — требуется рубидиевый стандарт или ежедневный re-sync.

## 12.3. GNSS spoofing/jamming

Multi-constellation GPS/GLONASS/Galileo/BeiDou; carrier-phase consistency; SQM; acceleration/jerk limits; консистентность с PTP/OCXO; RAIM/ANF; детекция скачков позиции/времени; jamming по C/N0; fallback PTP/holdover; журнал.

## 12.4. Артефакты

Графики Allan deviation; holdover test report; spoofing/jamming report; PTP conformance; datasheet приёмника + тест-векторы.

## 13.6. HSM API (PKCS#11, BC-16)

**Интерфейс:** PKCS#11 или утверждённый внутренний API.

**Требования:**

- HSM/криптопровайдер соответствует требованиям ФСБ/ФСТЭК для класса КС3 (BC-16);
- FIPS 140-3 — только supplementary/reference профиль (BC-16);
- no raw private key export;
- no plaintext key outside HSM/TEE;
- secure channel;
- audit;
- rate limiting ≤10 000 операций/с;
- session ≤1000 сессий/с.

**Ошибки:**

| Код | Значение |
|---|---|
| `HSM_SESSION` | Ошибка сессии |
| `HSM_AUTH` | Ошибка аутентификации |
| `HSM_TAMPER` | Tamper detected |
| `HSM_RATE_LIMIT` | Rate limit |
| `HSM_KEY_MISSING` | Ключ отсутствует |
| `HSM_POLICY` | Нарушение политики |
| `HSM_SELF_TEST_FAILED` | Self-test failed |
| `HSM_BUFFER_TOO_SMALL` | Буфер вызывающей стороны недостаточен (BC-18) |

`HSM_OK` в enum ошибок отсутствует (C-03): успех = `Ok(())`.

## 13.9. Power Sequencing (с BC-25)

**Включение:**
```
1. VIN protection healthy;
2. 5 V rail;
3. 3,3 V IO;
4. 1,8 V;
5. 1,2 V logic;
6. 0,85 V core multi-phase ramp;
7. HSM rail;
8. Optical transceiver rail;
9. Deassert reset;
10. Start bootloader.
```

**Выключение:**
```
1. Stop control services;
2. Flush logs;
3. Zeroize session keys;
4. Disable HSM operations;
5. Ramp down core;
6. Ramp down optical/HSM rails;
7. Ramp down IO;
8. Ramp down 5 V;
9. Save nonvolatile state;
10. Cut VIN.
```

**Brownout:** safe shutdown, запрет записи во flash при undervoltage, supercap/battery holdover.

## 13.10. Reset Strategy

| Тип | Домен | Действие | Время |
|---|---|---|---|
| POR | All | Full reset | 100 мс |
| External | All | Full reset | 100 мс |
| Watchdog | Core | Core reset | 50 мс |
| Software | Per-domain | Domain reset | 10 мс |
| Tamper | HSM | Lockdown + zeroization | ≤1 мс trigger, ≤2 с completion |
| Recovery | Control | Recovery mode | 500 мс |

**Правила:**
- reset domains изолированы;
- критические состояния в FRAM/MRAM с MAC;
- volatile keys zeroized при tamper (не при normal reset);
- rollback counter увеличивается только при successful boot (BC-24);
- boot attempt counter;
- после 3 неудач — recovery/lockdown.

## 13.11. CDC (Clock Domain Crossing)

- async FIFO с Gray pointer;
- handshake для одиночных сигналов;
- synchronizer chains ≥2 FF;
- constraints в SDC;
- CDC lint;
- formal CDC check;
- no combinational paths across domains;
- reset synchronizers;
- metastability MTBF расчёт.

## 13.13. Interrupt Behavior

- ISR минимальная;
- no blocking calls;
- no malloc;
- no logging в ISR кроме ring buffer;
- priority map утверждён;
- nested interrupts ограничены;
- error interrupts → safe state;
- spurious interrupt counter;
- interrupt latency budget.

## 13.14. DMA Descriptors

- descriptor rings;

- IOMMU/SMMU где доступно;

## 13.16. Интерфейсные state machines

### 13.16.1. Boot FSM

```
POWER_ON
  → ROM_VERIFY_PBL
  → PBL_VERIFY_SBL
  → SBL_VERIFY_KERNEL
  → KERNEL_START
  → CONTROL_SERVICES_START
  → HSM_ATTEST
  → KEY_RELEASE_POLICY_CHECK
  → RUNTIME_READY

Failure paths:
  → BOOT_FAIL_COUNT++
  → if count < 3: RETRY
  → if count >= 3: RECOVERY_MODE
  → if tamper: LOCKDOWN + ZEROIZE
```

### 13.16.2. Update FSM (с BC-24)

```
IDLE
  → FETCH_MANIFEST
  → VERIFY_SIGNATURE
  → CHECK_POLICY
  → FETCH_PAYLOAD
  → VERIFY_HASH
  → WRITE_INACTIVE_SLOT
  → SET_PENDING_METADATA
  → REBOOT

After reboot:
  → SELF_TEST
  → if OK:
      COMMIT_ROLLBACK_COUNTER
      MARK_SUCCESSFUL
      CLEAR_PENDING_METADATA
      → IDLE
  → if FAIL:
      MARK_FAILED
      RESTORE_PREVIOUS_SLOT
      DO_NOT_COMMIT_ROLLBACK_COUNTER
      → REBOOT/RECOVERY
```

**UPDATE-ROLLBACK-001 (BC-24):**
```
MUST: active rollback counter не увеличивается до успешного boot и self-test нового образа.
MUST: pending rollback counter хранится отдельно от active rollback counter.
MUST: при неудачном boot активный rollback counter остаётся прежним.
MUST: повторные неудачи приводят к recovery/lockdown по политике.
MUST: recovery mode не обходит signature, rollback policy и pending metadata validation.
V: T/F
```

### 13.16.3. Attestation FSM

```
IDLE
  → RECEIVE_NONCE
  → COLLECT_PCRS
  → COLLECT_HSM_STATUS
  → COLLECT_MODEL_HASHES
  → SERIALIZE_CBOR
  → SIGN_COSE_SIGN1
  → RETURN_REPORT

Failure:
  → ERROR + AUDIT
```

### 13.16.4. Consensus FSM (с BC-23)

```
INIT
  → BACKUP
  → on proposal: PREPARE
  → if quorum prepare: COMMIT
  → if quorum commit: FINALIZED
  → on timeout: VIEW_CHANGE
  → if view quorum: NEW_VIEW
  → if partition: DEGRADED
  → if quorum lost: ISOLATED
  → if rejoin: SYNC/RECOVERY
  → if equivocation/byzantine evidence: QUARANTINE/EVIDENCE_LOG
```

**CONS-FSM-001 (BC-23):**
```
MUST: FSM использует BFT-состояния: BACKUP, PREPARE, COMMIT, FINALIZED, VIEW_CHANGE, NEW_VIEW, DEGRADED, ISOLATED, SYNC/RECOVERY, QUARANTINE, EVIDENCE_LOG.
MUST: термины candidate/leader из Raft не используются как нормативные.
MAY: leader упоминается только как proposer/primary в рамках BFT-протокола при явном определении в ICD-1.
V: I/F
```

**Связь FSM ↔ требования:**

| FSM state | Требование |
|---|---|
| PREPARE | CONS-LAT-001 |
| COMMIT | CONS-LAT-002 |
| FINALIZED | CONS-003, REL-004 |
| VIEW_CHANGE | CONS-LAT-004 |
| QUARANTINE | BFT evidence accountability |
| SYNC/RECOVERY | CONS-004, REL-005 |

### 13.16.5. Lockdown FSM

```
NORMAL
  → if tamper: TAMPER_DETECTED
  → if compromise: COMPROMISE_DETECTED
  → LOCK_HSM
  → ZEROIZE_KEYS
  → STOP_CONTROL_SERVICES
  → SECURE_LOCKDOWN
  → if ceremony: RECOVERY
  → if policy: DECOMMISSION
```

### 13.16.6. Decommission FSM

```
ACTIVE
  → AUTHORIZE (3 of 5 + signature)
  → LOCKED
  → SANITIZING
  → VERIFY_SANITIZATION
  → DECOMMISSIONED
  → if re-provision: REPROVISIONED
  → if destroy: DESTROYED
```

## 13.19. API specification (API-1) — спецификация

### 13.19.1. Плоскости и транспорт

| Плоскость | API | Требования |
|---|---|---|
| Control | gRPC/CBOR поверх mTLS 1.3 + PQ-hybrid | идемпотентность, sequence, подписанные команды, RBAC/ABAC |
| Crypto | PKCS#11 поверх HSM-agent | no key export, rate limit, audit |
| Observability | OTLP/syslog CEF/OCSF | signed telemetry |
| Management | REST/OpenAPI (изолированная плоскость) | schema validation, MFA |
| AI/Model | signed manifest + registry API | attestation, allowlist |

### 13.19.2. Control API — операции

| Операция | Запрос (ключевые поля) | Ответ | Ограничения |
|---|---|---|---|
| SubmitCommand | plan_id, command_id, seq, payload, cmd_sig, authz_token, idempotency_key | result, error_code (13.8) | идемпотентность по command_id; monotonic seq; подпись оператора обязательна |
| GetStatus | node_id / cluster_id | state, pcr_map, hsm_status, time_quality | read-only, rate limited |
| ConsensusVote | height, view, block_hash, vote_sig | accepted / rejected | view = current; голос без подписи отвергается |
| RequestAttestation | nonce (≥16 Б) | AttestationReport (13.7) | nonce одноразовый; срок отчёта ≤60 с |
| EmergencyStop | reason_code, op_sig, second_op_sig | result, log_ref | two-person rule; hardware interlock; immutable log |
| UpdateCommit | manifest_hash, sid, attestation | UpdateResult::Pending | attest(sid, nonce); policy до slot swap |

### 13.19.3. Контракт ошибок и версионирование

Каждый ответ содержит: `result` (OK / error_code из 13.8), `request_seq` (эхо), `audit_ref` (ссылка на запись журнала).

Отрицательные ответы категорий CRITICAL/FATAL не подавляются клиентом — дублируются в SIEM.

Версия API — в заголовке пакета (major.minor): breaking changes — только через major + change board; предыдущая major поддерживается ≤2 релизов. Schema validation на gateway: несовместимый пакет отвергается до обработки.

## 13.20. Идемпотентность, replay protection, backward compatibility (BC-27)

### 13.20.1. Идемпотентность

```
IDEMP-001 (BC-27)
MUST: все управляющие команды, OTA-операции, audit export requests, key ceremony requests имеют idempotency key.
MUST: idempotency key привязан к actor, session, command type, payload hash и time window.
MUST: повторный запрос с тем же idempotency key возвращает предыдущий результат или статус обработки, но не повторяет побочный эффект.
MUST: idempotency store защищён от rollback и compartmentalization breach.
V: T/F
```

### 13.20.2. Защита от повторной передачи

```
REPLAY-001 (BC-27)
MUST: используются nonce, sequence number, timestamp window и channel binding.
MUST: control commands отклоняются при replay, seq out of window, timestamp skew, transcript mismatch.
MUST: audit события replay attempts фиксируются с error code.
V: T
```

### 13.20.3. Обратная совместимость

```
COMPAT-001 (BC-27)
MUST: интерфейсы версионируются.
MUST: silent downgrade запрещён.
MUST: deprecated поля имеют период миграции и approval change board.
MUST: compatibility matrix HW/SW/crypto/model/policy поддерживается в CM-1 и ПО-1.
MUST: API-1 содержит contract tests для backward compatibility.
V: I/T
```

**Связь с DM-1/API-1:**
- DM-1 определяет canonical serialization для idempotency key, command payload, audit record и attestation report;
- API-1 содержит примеры успешной и неуспешной идемпотентной повторной отправки SubmitCommand.

## 13.21. Gate-условия для ICD

- ICD-1 полный (все интерфейсы, FSM, security bindings, error codes, rate limits, idempotency keys, replay protection, backward compatibility policy) — **Gate 2 (CDR)**;
- ICD-1 утверждён — до layout и firmware freeze;
- ICD-1 обновляется через change board при любом изменении.

# 21. ТРЕБОВАНИЯ К ПРОГРАММНОМУ ОБЕСПЕЧЕНИЮ

## 21.1. Архитектура ПО

| Зона | Назначение | Технологии | Ограничения |
|---|---|---|---|
| Control Plane | Консенсус, управление, безопасность | Rust, C++, RTOS | Hard real-time, формальная верификация |
| Data Plane | TSN, DDS, CRDT transport | Rust/C++ | Детерминизм, backpressure |
| AI Plane | Инференс/обучение (T8) | C++, Rust, MLIR/LLVM, ONNX-совместимый backend | Sandbox, model attestation |
| Management Plane | API, UI, отчёты | Python/Go/TypeScript | Изолированно, non-control |
| Crypto Plane | HSM, PKI, ключи | Сертифицированные библиотеки, Rust/C | Запрет экспорта ключей |
| Observability | Логи, метрики, трейсы, SIEM | Открытые стандарты | Immutable audit |

**Запрет:** Python/FastAPI в управляющем контуре.

## 21.2. Toolchain и версии

### 21.2.1. Rust (BC-9, сохранено)

- **edition 2021** (edition 2024 требует rustc ≥1.85 и несовместим с pinned 1.83.0);
- миграция на edition 2024 — отдельным изменением после аудита toolchain ≥1.85 (BC-9, R-037, Deferred до v1.1);
- validated pinned toolchain;
- критерии выбора: воспроизводимость сборок, поддержка целевых архитектур, отсутствие известных critical CVE, long-term security patches;
- pinned через `rust-toolchain.toml`.

```toml
[toolchain]
channel = "1.83.0"  # [TBD] — фиксируется в ПО-1
components = ["rustfmt", "clippy", "rust-src"]
targets = ["riscv64imac-unknown-none-elf", "aarch64-unknown-linux-gnu"]
profile = "minimal"
```

### 21.2.2. LLVM/MLIR

Версия фиксируется в ПО-1 как pinned. Upgrade policy: квартальный ревью, окно security-патчей, regression suite, никаких тихих обновлений в production.

### 21.2.3. C/C++

- MISRA C/C++ актуальной редакции для критических модулей;
- только при необходимости;
- обязательны sanitizers, static analysis, peer review.

## 21.3. RTOS, hypervisor, TEE

- **RTOS:** микроядерная или строго изолированная; preemptive scheduling; MPU/MMU isolation; priority inheritance/ceiling; детерминированные прерывания; сертификационный потенциал; наличие в реестре российского ПО либо обоснованный risk acceptance. Кандидаты — ПО-1.
- **Hypervisor:** не обязателен в baseline; изоляция обеспечивается RTOS/MPU, hardware enclaves, process separation. Type-1 — опционально, только сертифицированный, после отдельного safety/security case.
- **TEE:** secure enclave на базе сертифицированного HSM/криптомодуля. CPU TEE (TrustZone и аналоги) не является единственным root of trust. Model attestation: signed manifest → HSM-backed verification → sandboxed runtime → remote attestation → allowlist операторов.

## 21.4. Real-time и детерминизм

Fixed-priority preemptive scheduling; priority inheritance/ceiling; no unbounded dynamic allocation в steady state; memory pools; watchdog hierarchy; WCET analysis; stack usage analysis; no GC в control plane; TSN shaping/policing; overload protection; graceful degradation; fail-safe/fail-secure.

## 21.5. WCET методика (BC-31)

```
WCET-001 (v2.3, BC-31)
MUST: WCET + interrupt latency + network jitter ≤ deadline с запасом не менее 20%.
TARGET: запас не менее 50% для safety-critical tasks.
STRETCH: запас не менее 70% для критических управляющих контуров при подтверждённой модели нагрузки.
V: T/A/S/F
```

**Шаги:**

1. Статический анализ loop bounds и call graph;
2. Измерение на худших входных данных в HIL/SIL;
3. Учёт pipeline/cache/branch prediction worst case;
4. **Применение целевого запаса:**
   - не менее 20% как обязательный minimum;
   - не менее 50% как target для safety-critical задач;
   - повышенный запас по решению safety case.
5. Формальное доказательство для функций списка 21.6.

## 21.6. Safety-critical список для MC/DC (100%)

1. Consensus finalize;
2. View change BFT↔CFT;
3. Quorum evaluation;
4. Key release policy;
5. Tamper detection/zeroization;

### 22.1.3. Rust реализация заголовка (C-08)

Явный парсер по байтовым смещениям с полной проверкой полей (вместо `#[repr(C, packed)]`):

```rust
// fw/bootloader/src/image.rs — v2.3
pub const FLAG_ENCRYPTED: u8 = 0x01;
pub const FLAG_SIGNED: u8    = 0x02;
pub const FLAG_ROLLBACK: u8  = 0x04;

pub const IMAGE_TYPE_BOOTLOADER: u8 = 0x01;
pub const IMAGE_TYPE_KERNEL:     u8 = 0x02;
pub const IMAGE_TYPE_APP:        u8 = 0x03;
pub const IMAGE_TYPE_MODEL:      u8 = 0x04;

// Фиксированная часть заголовка — 114 байт, смещения жёсткие:
const OFF_MAGIC: usize     = 0;    // 4 B
const OFF_VERSION: usize   = 4;    // 4 B
const OFF_MIN_HW_REV:usize = 8;    // 2 B
const OFF_TYPE: usize      = 10;   // 1 B
const OFF_FLAGS: usize     = 11;   // 1 B
const OFF_SIZE: usize      = 12;   // 4 B
const OFF_HASH_ALG: usize  = 16;   // 1 B
const OFF_HASH: usize      = 17;   // 64 B (слот под Стрибог-512)
const OFF_SIGNER: usize    = 81;   // 16 B
const OFF_SIG_ALG: usize   = 97;   // 1 B
const OFF_ROLLBACK: usize  = 98;   // 4 B
const OFF_TIMESTAMP: usize = 102;  // 8 B
const OFF_CERT_LEN: usize  = 110;  // 2 B
const OFF_SIG_LEN: usize   = 112;  // 2 B
const HEADER_LEN: usize    = 114;

pub struct ImageHeader {
    pub version: u32,
    pub min_hw_rev: u16,
    pub image_type: u8,
    pub flags: u8,
    pub payload_size: u32,
    pub payload_hash_alg: u8,
    pub payload_hash: [u8; 64],
    pub signer_id: [u8; 16],
    pub signature_alg: u8,
    pub rollback_counter: u32,
    pub timestamp: u64,
}

pub struct ParsedImage<'a> {
    pub header: ImageHeader,
    pub payload: &'a [u8],
    pub cert_chain: &'a [u8],
    pub signature: &'a [u8],
}

impl ImageHeader {
    pub fn parse(buf: &[u8]) -> Result<ImageHeader, BootError> {
        if buf.len() < HEADER_LEN {
            return Err(BootError::HeaderTooShort);
        }
        if &buf[OFF_MAGIC..OFF_MAGIC + 4] != b"SAKU" {
            return Err(BootError::BadMagic);
        }
        let mut hash = [0u8; 64];
        hash.copy_from_slice(&buf[OFF_HASH..OFF_HASH + 64]);
        let mut signer = [0u8; 16];
        signer.copy_from_slice(&buf[OFF_SIGNER..OFF_SIGNER + 16]);
        Ok(ImageHeader {
            version:        u32::from_be_bytes(buf[OFF_VERSION..OFF_VERSION + 4].try_into().unwrap()),
            min_hw_rev:     u16::from_be_bytes(buf[OFF_MIN_HW_REV..OFF_MIN_HW_REV + 2].try_into().unwrap()),
            image_type:     buf[OFF_TYPE],
            flags:          buf[OFF_FLAGS],
            payload_size:   u32::from_be_bytes(buf[OFF_SIZE..OFF_SIZE + 4].try_into().unwrap()),
            payload_hash_alg: buf[OFF_HASH_ALG],
            payload_hash:   hash,
            signer_id:      signer,
            signature_alg:  buf[OFF_SIG_ALG],
            rollback_counter: u32::from_be_bytes(buf[OFF_ROLLBACK..OFF_ROLLBACK + 4].try_into().unwrap()),
            timestamp:      u64::from_be_bytes(buf[OFF_TIMESTAMP..OFF_TIMESTAMP + 8].try_into().unwrap()),
        })
    }
}

pub fn parse_image(buf: &[u8]) -> Result<ParsedImage<'_>, BootError> {
    let header = ImageHeader::parse(buf)?;
    let payload = buf.get(HEADER_LEN..HEADER_LEN + header.payload_size as usize)
        .ok_or(BootError::PayloadSizeMismatch)?;
    let mut off = HEADER_LEN + header.payload_size as usize;
    let cert_len = u16::from_be_bytes(buf[off - 2..off].try_into().unwrap()) as usize;
    let cert_chain = buf.get(off..off + cert_len).ok_or(BootError::Truncated)?;
    off += cert_len;
    let signature = buf.get(off..).ok_or(BootError::Truncated)?;
    Ok(ParsedImage { header, payload, cert_chain, signature })
}

pub struct DeviceState {
    pub hw_rev: u16,
    pub now_s: Option<u64>,
    pub min_versions: [u32; 4],
}

impl ParsedImage<'_> {
    pub fn verify(&self, anchor: &TrustAnchor, device: &DeviceState) -> Result<(), BootError> {
        let h = &self.header;
        if h.flags & FLAG_SIGNED == 0 {
            return Err(BootError::Unsigned);
        }
        if h.payload_size as usize != self.payload.len() {
            return Err(BootError::PayloadSizeMismatch);
        }
        if h.min_hw_rev > device.hw_rev {
            return Err(BootError::HwRevMismatch);
        }
        let idx = (h.image_type.wrapping_sub(1) as usize).min(3);
        if h.rollback_counter < device.min_versions[idx] {
            return Err(BootError::RollbackRejected);
        }
        if let Some(now) = device.now_s {
            if h.timestamp > now + 60 {
                return Err(BootError::TimestampInvalid);
            }
        }
        let expected = match h.payload_hash_alg {
            ALG_STREEBOG_256 => &h.payload_hash[..32],
            ALG_STREEBOG_512 => &h.payload_hash,
            _ => return Err(BootError::UnsupportedHashAlg),
        };
        anchor.verify_hybrid(self.payload, expected, self.cert_chain,
                              self.signature, h.signature_alg)
    }
}
```

## 22.10. Clock Domain Crossing

```verilog
// fw/hdl/cdc_sync.v
module cdc_sync #(
    parameter WIDTH = 1,
    parameter STAGES = 2
) (
    input  wire              dst_clk,
    input  wire              dst_rst_n,
    input  wire [WIDTH-1:0]  async_in,
    output wire [WIDTH-1:0]  sync_out
);
    (* ASYNC_REG = "TRUE" *)
    reg [WIDTH-1:0] sync_chain [0:STAGES-1];
    integer i;

    always @(posedge dst_clk or negedge dst_rst_n) begin
        if (!dst_rst_n) begin
            for (i = 0; i < STAGES; i = i + 1)
                sync_chain[i] <= {WIDTH{1'b0}};
        end else begin
            sync_chain[0] <= async_in;
            for (i = 1; i < STAGES; i = i + 1)
                sync_chain[i] <= sync_chain[i-1];
        end
    end

    assign sync_out = sync_chain[STAGES-1];
endmodule
```

## 22.11. Watchdog hierarchy (C-05)

Исправленная реализация window_wdt.v:

```verilog
// fw/hdl/window_wdt.v — v2.3
module window_wdt #(
    parameter CLK_HZ = 100_000_000,
    parameter MIN_MS = 50,
    parameter MAX_MS = 200
) (
    input  wire clk,
    input  wire rst_n,
    input  wire kick,
    output reg  timeout      // sticky: снимается только аппаратным сбросом
);
    localparam MIN_CYCLES = (CLK_HZ / 1000) * MIN_MS;
    localparam MAX_CYCLES = (CLK_HZ / 1000) * MAX_MS;

    reg [31:0] counter;
    reg        armed;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            counter <= 32'd0;
            armed   <= 1'b1;
            timeout <= 1'b0;
        end else if (kick) begin
            if (armed && counter < MIN_CYCLES) begin
                timeout <= 1'b1;
            end else begin
                counter <= 32'd0;
                armed   <= 1'b1;
            end
        end else if (armed && counter >= MAX_CYCLES) begin
            timeout <= 1'b1;
            armed   <= 1'b0;
        end else begin
            counter <= counter + 32'd1;
        end
    end
endmodule
```

Свойства: kick в границе [MIN, MAX] включительно валиден; после валидного kick окно перезапускается; timeout защёлкнут до аппаратного сброса; после просрочки подсчёт остановлен.

| Watchdog | Timeout | Действие |
|---|---:|---|
| Core window WDT | 50–200 мс | reset core |
| System manager WDT | 500 мс | safe state |
| HSM WDT | 1 с | lockdown HSM |
| Power WDT | 2 с | controlled shutdown |
| Communication WDT | 3 с | reconnect/degrade |

```verilog
);
    reg [ADDR_W+LEN_W-1:0] mem [0:DEPTH-1];
    reg [$clog2(DEPTH):0]   head, tail;

    assign producer_ready = ((head - tail) != DEPTH);
    assign consumer_valid = (head != tail);
    assign {consumer_addr, consumer_len} = mem[tail[$clog2(DEPTH)-1:0]];

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            head <= 0;
            tail <= 0;
        end else begin
            if (producer_valid && producer_ready) begin
                mem[head[$clog2(DEPTH)-1:0]] <= {producer_addr, producer_len};
                head <= head + 1;
            end
            if (consumer_valid && consumer_ready)
                tail <= tail + 1;
        end
    end
endmodule
```

Требования: DMA bounds проверяются аппаратно; no access к secure memory; IOMMU для внешних мастер-портов.

## 22.23. Update agent (C-04, BC-24)

Процесс: fetch manifest → verify signature/policy → compatibility check → download delta/full → verify hash → write inactive slot → **set pending metadata** → reboot attempt → confirm health → **commit rollback counter после successful boot** → mark successful/rollback.

Вызов `attest(sid, nonce)` с явной сессией (C-04). Pending rollback counter (BC-24).

```rust
// fw/update-agent/src/lib.rs — v2.3 (фрагмент)
impl UpdateAgent {
    pub fn apply(&mut self, pkg: UpdatePackage) -> Result<UpdateResult, UpdateError> {
        let manifest = pkg.manifest();
        self.verify_signature(&manifest)?;
        self.policy.check(&manifest)?;

        let sid = self.hsm.open_session(&self.session_pin)
            .map_err(|_| UpdateError::HsmUnavailable)?;
        let attest = self.hsm.attest(sid, &manifest.nonce, &mut self.attest_buf)
            .map_err(|_| UpdateError::AttestationFailed)?;
        self.hsm.close_session(sid)
            .map_err(|_| UpdateError::HsmUnavailable)?;
        self.verify_attestation(&attest, &manifest.expected_policy)?;

        let payload = pkg.payload();
        if !self.verify_hash(payload, &manifest.payload_hash) {
            return Err(UpdateError::HashMismatch);
        }

        let slot = self.storage.inactive_slot();
        self.storage.write(slot, payload)?;
        self.storage.set_metadata(slot, &manifest)?;
        self.storage.set_pending_rollback_counter(slot, manifest.rollback_counter)?;
        self.storage.set_boot_slot(slot)?;
        self.request_reboot();
        Ok(UpdateResult::Pending)
    }

    pub fn confirm_health(&mut self) -> Result<(), UpdateError> {
        let health = self.self_test()?;
        if health.is_ok() {
            self.storage.commit_rollback_counter()?;   // BC-24
            self.storage.mark_successful()?;
            self.storage.clear_pending_metadata()?;
        } else {
            self.storage.mark_failed()?;
            self.storage.restore_previous_slot()?;
            // rollback counter НЕ коммитится
            self.request_reboot();
        }
        Ok(())
    }
}
```

### 23.2.3. Rust реализация ГОСТ KDF (C-09)

```rust
// sw/crypto/src/kdf.rs — v2.3
// Streebog256/512 — обёртки над сертифицированной реализацией (КР-1).
pub struct Streebog256;
pub struct Streebog512;
impl Digest for Streebog256 { /* вызов сертифицированной библиотеки */ }
impl Digest for Streebog512 { /* вызов сертифицированной библиотеки */ }

type HmacStreebog256 = Hmac<Streebog256>;

pub fn hkdf_streebog256(ikm: &[u8], salt: &[u8], info: &[u8], out_len: usize) -> Vec<u8> {
    let mut mac = HmacStreebog256::new_from_slice(salt)
        .expect("HMAC принимает ключ любого размера");
    mac.update(ikm);
    let prk = mac.finalize().into_bytes();

    let mut okm = Vec::with_capacity(out_len);
    let mut t: Vec<u8> = Vec::new();
    let mut counter: u8 = 1;
    while okm.len() < out_len {
        let mut mac = HmacStreebog256::new_from_slice(&prk)
            .expect("HMAC принимает ключ любого размера");
        mac.update(&t);
        mac.update(info);
        mac.update(&[counter]);
        t = mac.finalize().into_bytes().to_vec();
        okm.extend_from_slice(&t);
        counter = counter.checked_add(1).expect("переполнение HKDF-счётчика");
    }
    okm.truncate(out_len);
    okm
}
```

```rust
// sw/crypto/src/hybrid.rs
pub fn hybrid_kem_combine(
    ss_gost: &[u8],       // VKO ГОСТ Р 34.10-2012
    ss_pq: &[u8],         // ML-KEM-1024
    context_salt: &[u8],
    protocol: &str,
    epoch: u64,
) -> Vec<u8> {
    let mut ikm = Vec::new();
    ikm.extend_from_slice(ss_gost);
    ikm.extend_from_slice(ss_pq);

    let mut info = Vec::new();
    info.extend_from_slice(b"HYBRID-KEM");
    info.extend_from_slice(protocol.as_bytes());
    info.extend_from_slice(&epoch.to_be_bytes());

    hkdf_streebog256(&ikm, context_salt, &info, 32)
}
```

## 27.1. Консенсус (C-01)

```rust
// sw/consensus/src/lib.rs — v2.3
use std::collections::{HashMap, HashSet};
use crate::crypto::Streebog256;

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum ConsensusMode { Bft, Cft }

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum ConsensusError {
    NotLeader,
    QuorumNotReached,
    InvalidSignature,
    StaleView,
    DoubleFinalization,
    ViewChangeInProgress,
}

#[derive(Clone, Debug)]
pub struct Block {
    pub height: u64,
    pub view: u64,
    pub parent_hash: [u8; 32],
    pub payload: Vec<u8>,
    pub proposer: u32,
}

impl Block {
    pub fn hash(&self) -> [u8; 32] {
        let mut hasher = Streebog256::new();
        hasher.update(&self.height.to_be_bytes());
        hasher.update(&self.view.to_be_bytes());
        hasher.update(&self.parent_hash);
        hasher.update(&self.payload);
        hasher.update(&self.proposer.to_be_bytes());
        let mut out = [0u8; 32];
        out.copy_from_slice(&hasher.finalize());
        out
    }
}

#[derive(Clone, Debug)]
pub struct Vote {
    pub block_hash: [u8; 32],
    pub voter: u32,
    pub view: u64,
    pub signature: Vec<u8>,
}

pub trait ConsensusNode {
    fn propose(&mut self, payload: Vec<u8>) -> Result<Block, ConsensusError>;
    fn vote(&mut self, block: &Block) -> Result<Vote, ConsensusError>;
    fn on_vote(&mut self, vote: &Vote, sig_valid: bool) -> Result<bool, ConsensusError>;
    fn finalize(&mut self, block: &Block) -> Result<(), ConsensusError>;
    fn view_change(&mut self, new_view: u64) -> Result<(), ConsensusError>;
    fn mode(&self) -> ConsensusMode;
}

pub struct BftNode {
    id: u32,
    total: u32,
    f: u32,
    view: u64,
    height: u64,
    parent: [u8; 32],
    finalized: HashMap<u64, [u8; 32]>,
    votes: HashMap<[u8; 32], HashSet<u32>>,
    verifier: Box<dyn SignatureVerifier>,
}

impl BftNode {
    pub fn new(id: u32, total: u32, verifier: Box<dyn SignatureVerifier>) -> Self {
        let f = (total - 1) / 3;
        Self { id, total, f, view: 0, height: 0, parent: [0u8; 32],
               finalized: HashMap::new(), votes: HashMap::new(), verifier }
    }

    pub fn quorum(&self) -> usize { (2 * self.f + 1) as usize }

    pub fn is_leader(&self, view: u64) -> bool {
        (view % self.total as u64) as u32 == self.id
    }
}

impl ConsensusNode for BftNode {
    fn propose(&mut self, payload: Vec<u8>) -> Result<Block, ConsensusError> {
        if !self.is_leader(self.view) {
            return Err(ConsensusError::NotLeader);
        }
        Ok(Block {
            height: self.height,
            view: self.view,
            parent_hash: self.parent,
            payload,
            proposer: self.id,
        })
    }

    fn vote(&mut self, block: &Block) -> Result<Vote, ConsensusError> {
        if block.view != self.view {
            return Err(ConsensusError::StaleView);
        }
        let sig = self.verifier.sign(&block.hash())?;
        Ok(Vote { block_hash: block.hash(), voter: self.id, view: self.view, signature: sig })
    }

    fn on_vote(&mut self, vote: &Vote, sig_valid: bool) -> Result<bool, ConsensusError> {
        if !sig_valid {
            return Err(ConsensusError::InvalidSignature);
        }
        if vote.view != self.view {
            return Err(ConsensusError::StaleView);
        }
        let set = self.votes.entry(vote.block_hash).or_default();
        set.insert(vote.voter);
        Ok(set.len() >= self.quorum())
    }

    fn finalize(&mut self, block: &Block) -> Result<(), ConsensusError> {
        let n = self.votes.get(&block.hash()).map(|s| s.len()).unwrap_or(0);
        if n < self.quorum() {
            return Err(ConsensusError::QuorumNotReached);
        }
        match self.finalized.get(&block.height) {
            Some(existing) if *existing != block.hash() =>
                return Err(ConsensusError::DoubleFinalization),
            Some(_) => return Ok(()),
            None => {}
        }
        self.finalized.insert(block.height, block.hash());
        self.height += 1;
        self.parent = block.hash();
        Ok(())
    }

    fn view_change(&mut self, new_view: u64) -> Result<(), ConsensusError> {
        if new_view <= self.view {
            return Err(ConsensusError::ViewChangeInProgress);
        }
        self.view = new_view;
        Ok(())
    }

    fn mode(&self) -> ConsensusMode { ConsensusMode::Bft }
}
```

**Свойства:** голос без подписи не учитывается; повторный голос того же узла не увеличивает кворум; блок чужой/устаревшей view отвергается; двойная финализация одной высоты с разным hash невозможна.

## 27.2. Secure boot verification (C-02)

```rust
// fw/bootloader/src/verify.rs — v2.3
pub struct TrustAnchor {
    root_pubkey: [u8; 64],
    crl: Vec<[u8; 16]>,
}

impl TrustAnchor {
    pub fn verify_hybrid(
        &self,
        payload: &[u8],
        expected_hash: &[u8],
        cert: &SignerCert,
        signature: &[u8],
        alg: u8,
    ) -> Result<(), BootError> {
        let actual_hash = streebog512(payload);
        if actual_hash.as_slice() != expected_hash {
            return Err(BootError::HashMismatch);
        }

        if !cert.issued_by(&self.root_pubkey) {
            return Err(BootError::ChainInvalid);
        }
        if !cert.time_valid() {
            return Err(BootError::CertExpired);
        }

        if self.crl.contains(cert.key_id()) {
            return Err(BootError::Revoked);
        }

        let (gost_sig, pq_sig) = split_hybrid_signature(signature, alg)?;
        if !gost_verify(cert.gost_pubkey(), payload, gost_sig) {
            return Err(BootError::GostSignatureInvalid);
        }
        if !pq_verify(cert.pq_pubkey(), payload, pq_sig) {
            return Err(BootError::PqSignatureInvalid);
        }
        Ok(())
    }
}

fn split_hybrid_signature(sig: &[u8], alg: u8) -> Result<(&[u8], &[u8]), BootError> {
    match alg {
        ALG_GOST_PLUS_MLDSA65 => {
            const GOST_LEN: usize = 64;
            if sig.len() < GOST_LEN {
                return Err(BootError::SignatureTooShort);
            }
            Ok((&sig[..GOST_LEN], &sig[GOST_LEN..]))
        }
        _ => Err(BootError::UnsupportedAlgorithm),
    }
}
```

```rust
    pub signature_alg: u16,
    pub signature: &'a [u8],  // variable-length
}

impl<'a> AttestationReport<'a> {
    pub fn encode(&self, out: &mut [u8]) -> Result<usize, AttestationError> {
        // Production: canonical CBOR serialization.
        Ok(0)
    }

    pub fn sign_into(
        &self,
        hsm: &mut dyn crate::hsm::HsmBackend,
        sid: crate::hsm::SessionId,
        key: crate::hsm::KeyHandle,
        sig_out: &mut [u8],
    ) -> Result<usize, AttestationError> {
        let mut payload = [0u8; 2048];
        let len = self.encode(&mut payload)
            .map_err(|_| AttestationError::CborEncode)?;

        hsm.sign(sid, key, &payload[..len], sig_out)
            .map_err(|_| AttestationError::SignFailed)
    }
}

#[derive(Debug)]
pub enum AttestationError {
    CborEncode,
    SignFailed,
    VerifyFailed,
    BufferTooSmall,
}
```

## 27.9. CRDT engine (Rust, C-06, BC-34)

```rust
// sw/crdt/src/lib.rs — v2.3 (BC-34)
use alloc::collections::BTreeMap;
use alloc::vec::Vec;
use alloc::string::String;

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct NodeId(pub u64);

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct VectorClock(pub BTreeMap<NodeId, u64>);

impl VectorClock {
    pub fn new() -> Self { Self(BTreeMap::new()) }

    pub fn increment(&mut self, node: NodeId) {
        *self.0.entry(node).or_insert(0) += 1;
    }

    pub fn merge(&mut self, other: &VectorClock) {
        for (k, v) in &other.0 {
            let entry = self.0.entry(*k).or_insert(0);
            *entry = (*entry).max(*v);
        }
    }

    pub fn happens_before(&self, other: &VectorClock) -> bool {
        let mut strictly_less = false;
        let mut all_keys = BTreeMap::new();
        for (k, v) in &self.0 { all_keys.insert(*k, *v); }
        for (k, v) in &other.0 {
            let entry = all_keys.entry(*k).or_insert(0);
            if *entry > *v { return false; }
            if *entry < *v { strictly_less = true; }
        }
        strictly_less
    }

    pub fn is_concurrent_with(&self, other: &VectorClock) -> bool {
        !self.happens_before(other)
            && !other.happens_before(self)
            && self != other
    }
}

#[derive(Clone, Debug)]
pub struct LwwMetadata {
    pub timestamp: u64,
    pub node_id: NodeId,
    pub value_hash: [u8; 32],
}

#[derive(Clone, Debug)]
pub enum CrdtValue {
    Counter(BTreeMap<NodeId, u64>),
    Register {
        value: Vec<u8>,
        clock: VectorClock,
        lww: LwwMetadata,
    },
}

pub enum CrdtOp {
    Increment { node: NodeId, delta: u64 },
    Set {
        value: Vec<u8>,
        clock: VectorClock,
        lww: LwwMetadata,
    },
}

pub struct CrdtEngine {
    state: BTreeMap<String, CrdtValue>,
}

impl CrdtEngine {
    pub fn new() -> Self { Self { state: BTreeMap::new() } }

    pub fn apply(&mut self, key: &str, op: CrdtOp) {
        match op {
            CrdtOp::Increment { node, delta } => {
                let entry = self.state.entry(String::from(key)).or_insert_with(|| {
                    CrdtValue::Counter(BTreeMap::new())
                });
                if let CrdtValue::Counter(counts) = entry {
                    *counts.entry(node).or_insert(0) += delta;
                }
            }
            CrdtOp::Set { value, clock, lww } => {
                let entry = self.state.entry(String::from(key)).or_insert(
                    CrdtValue::Register {
                        value: Vec::new(),
                        clock: VectorClock::new(),
                        lww: LwwMetadata {
                            timestamp: 0,
                            node_id: NodeId(0),
                            value_hash: [0u8; 32],
                        },
                    },
                );
                if let CrdtValue::Register {
                    value: old_value,
                    clock: old_clock,
                    lww: old_lww,
                } = entry
                {
                    if old_clock.happens_before(&clock) {
                        *old_value = value;
                        *old_clock = clock;
                        *old_lww = lww;
                    } else if clock.happens_before(old_clock) {
                        // Existing wins
                    } else if old_clock.is_concurrent_with(&clock) {
                        if is_new_lww_winner(old_lww, &lww) {
                            *old_value = value;
                            *old_clock = clock;
                            *old_lww = lww;
                        }
                    } else if old_clock == &clock {
                        if is_new_lww_winner(old_lww, &lww) {
                            *old_value = value;
                            *old_lww = lww;
                        }
                    }
                }
            }
        }
    }
}

fn is_new_lww_winner(old: &LwwMetadata, new: &LwwMetadata) -> bool {
    if new.timestamp != old.timestamp {
        return new.timestamp > old.timestamp;
    }
    if new.node_id != old.node_id {
        return new.node_id > old.node_id;
    }
    new.value_hash > old.value_hash
}
```

# 7. ПРОЦЕДУРА РЕГИСТРАЦИИ НОВЫХ BC

Для этапа приложений и последующих ревизий (v2.4+):

1. Новому BC присваивается следующий номер (**BC-37, BC-38, …**).
2. Регистрация — только через change board.
3. Обязательные поля по шаблону:
   - BC ID;
   - Источник (X-NN или иной);
   - Объект (затронутые разделы);
   - Было / Стало;
   - Тип (Breaking / Уточнение / Новое требование);
   - Митигация;
   - Owner;
   - Gate;
   - Статус (Closed / Open / Deferred);
   - Дата принятия;
   - Основание.
4. Обязательная привязка:
   - риск УР-1 (с P/I/RPN);
   - затрагиваемые приложения.
5. Обязательная строка:
   - в 29.2 (открытые позиции);
   - в шапке «Что нового» соответствующей ревизии.
6. Без регистрации в журнале изменение в приложения не вносится (запрет «молчаливых» breaking changes).
